# اتحادیار — پلتفرم وردپرسی هوش مصنوعی

**نسخهٔ تحویل:** هسته `1.8.0-phase9` · قالب `1.1.0` · تاریخ: ۲۶ شهریور ۱۴۰۴
**وضعیت تست:** ۷۵۱ assertion سبز روی ۹ فاز

---

## این بسته چیست

افزونهٔ اتحادیار (`etehadyar-v6.13.2`) به یک **پلتفرم دو تکه‌ای** تبدیل شده است:

| بخش | نقش |
|---|---|
| **افزونهٔ هستهٔ اتحادیار** (اجباری) | همهٔ منطق: ورود با موبایل، کیف پول، پرداخت، دسترسی‌ها، جداسازی دادهٔ کاربران، API |
| **قالب اتحادیار** | فقط ظاهر. هیچ `wpdb`، SQL یا منطق پرداختی ندارد |
| **افزونهٔ قدیمی (hotfix)** | نسخهٔ اصلاح‌شدهٔ افزونهٔ ۶.۱۳.۲ — موتور تولید محتوای AI |

> **چرا سه بسته و نه یکی؟** اگر منطق پرداخت و داده داخل قالب می‌بود، با هر تعویض قالب کل کیف پول و حساب کاربران از دست می‌رفت. این تفکیک یک تصمیم آگاهانه است، نه پیچیدگی اضافه.

---

## ترتیب نصب (مهم)

ترتیب اهمیت دارد؛ قالب بدون هسته فعال نمی‌شود.

### ۱. افزونهٔ هسته
پیشخوان → افزونه‌ها → افزودن → بارگذاری → `etehadyar-core-1.8.0-phase9.zip` → فعال‌سازی.

با فعال‌سازی، جدول‌ها و نقش‌های کاربری ساخته می‌شوند.

### ۲. افزونهٔ قدیمی (موتور AI)
همان مسیر با `etehadyar-6.13.2-hotfix.zip`.

> نسخهٔ اصلی گیت‌هاب را نصب **نکنید** — دو خطای کشنده و چند باگ امنیتی دارد که در این نسخه رفع شده‌اند.

### ۳. قالب
پیشخوان → نمایش → پوسته‌ها → افزودن → بارگذاری → `etehadyar-theme-1.1.0.zip` → فعال‌سازی.

با فعال‌سازی، سه صفحهٔ **داشبورد**، **استودیو**، **کیف پول** و **ورود** خودکار ساخته می‌شوند.

## تنظیمات پس از نصب

همه در **پیشخوان → پلتفرم اتحادیار**:

| صفحه | کار |
|---|---|
| **تنظیمات** | پنل پیامک (ملی‌پیامک) برای ورود با موبایل، و درگاه زرین‌پال |
| **مالی** | نرخ‌های مصرف (هر ۱۰۰ کلمه، هر تصویر، هر دقیقه صدا…) |
| **اتصال به گوگل** | سرچ کنسول — تا وصل نشود، بخش سئو صادقانه می‌گوید داده ندارد |
| **حافظهٔ معنایی** | ساخت ایندکس جست‌وجو |

### ⚠️ اگر ایندکس قدیمی دارید
بردارهای ساخته‌شده پیش از نسخهٔ `1.8.0` از `md5()` می‌آمدند و **بی‌ارزش‌اند**. در «حافظهٔ معنایی» یک‌بار «پاک‌کردن بردارهای قدیمی» و سپس «ساخت ایندکس» را بزنید.

## آنچه در این ۹ فاز انجام شد

### قابلیت‌های ساخته‌شده
- **ورود با شمارهٔ موبایل** — کد یک‌بارمصرف، محدودیت نرخ، کد هش‌شده در دیتابیس
- **کیف پول** — همهٔ مبالغ ریال صحیح (نه اعشاری)، دفتر کل فقط‌افزودنی، کسر اتمی
- **پرداخت زرین‌پال** — با تأیید دومرحله‌ای و بازیابی تراکنش معلق
- **استودیوی کاربری** — تولید محتوا، تصویر و صدا از فرانت‌اند با کسر خودکار اعتبار
- **جداسازی دادهٔ کاربران** — هیچ کاربری داده یا کار کاربر دیگر را نمی‌بیند
- **داشبورد و سئو** — فقط داده‌های واقعی

### باگ‌های رفع‌شده
| شناسه | موضوع | فاز |
|---|---|---|
| C1، C2 | دو خطای کشنده | هات‌فیکس |
| C3 | ستون‌های غایب پشتیبانی صوتی | ۷ |
| C4 | اندپوینت عمومی بدون محدودیت (نشت هزینهٔ OpenAI) | ۷ |
| C5 | «آپلود SVG» | ۷ — **هشدار کاذب، رد شد** |
| H2 | شمارش کلمات فارسی | ۴ |
| H4 | آمار سئوی ساختگی | ۸ |
| H5 | کوئری بی‌سقف محصولات | ۷ |
| H8 | نشت پوشه‌های موقت ویدیو | ۷ |
| H1 | امبدینگ جعلی `md5` | ۹ |
| M1 | ستون `level` گم‌شده در مهاجرت `activity_log` (خطا در هر بارگذاری صفحه) | ۱۰ |
| M2 | `dbDelta` همهٔ ایندکس‌ها را بی‌صدا دور می‌انداخت (کندی تدریجی) | ۱۰ |
| M3 | تعریف یک‌خطی جدول‌ها، غیرقابل تجزیه برای `dbDelta` | ۱۰ |
| M4 | هدر کهنهٔ `Tested up to` | ۱۰ |

### سه موردی که ارزش دانستن دارند

**۱. یک «باگ امنیتی» واقعی نبود.** C5 («آپلود SVG بدون پاک‌سازی») پس از بررسی، هشدار کاذب از آب درآمد: متن از قبل escape می‌شد و افزونه اصلاً آپلود SVG را باز نمی‌کرد. به‌جای نوشتن کدِ بی‌اثر، تست نگهبان گذاشته شد.

**۲. آمار داشبورد ساختگی بود.** «نرخ تبدیل» یا از `rand()` می‌آمد یا عدد ثابت `۳.۹٪` بود، و «درآمد کل» از `تعداد محصول × ۱۵۰٬۰۰۰` ساخته می‌شد. همه حذف شدند.

**۳. «جست‌وجوی معنایی» معنایی نبود.** بردارها از `md5()` می‌آمدند؛ افزودن یک نقطه به جمله، شباهت را به اندازهٔ یک موضوع کاملاً بی‌ربط کاهش می‌داد.

## نکتهٔ مهم پیش از استفادهٔ واقعی

همهٔ ۷۵۱ تست روی یک **شبیه‌ساز وردپرس با SQLite** اجرا شده‌اند. پیش از راه‌اندازی روی سایت واقعی، پیشنهاد می‌شود یک‌بار روی وردپرس خام با MySQL نصب و مسیر کامل (ثبت‌نام ← شارژ ← تولید محتوا ← کسر اعتبار) آزمایش شود. تفاوت‌های جزئی MySQL و SQLite تنها ریسک باقی‌مانده است.
